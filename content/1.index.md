## Who this helps

- PMs and engineers publishing change logs and how-tos quickly
- Customer-facing teams needing a single source of truth
- Small teams that want readable docs without a CMS install

## Real-world use cases

- Ship a feature update with a clear “what changed” and next steps
- Maintain a lightweight runbook with troubleshooting steps
- Publish onboarding guides with links to the product and support

## Flow

1. Write or edit Markdown in `content/`
2. Use `::button-link` for primary actions and ghost variant for secondary
3. Preview locally, then generate static or build for your host

## Practical defaults

- Auto nav from front-matter `navigation.title`
- Focus-visible controls and larger tap targets
- Light/dark mode that follows system preference
- Prebuilt call-to-action buttons and markdown callouts

## Quick start

```bash
npm install
npm run dev
```

Open http://localhost:3000 and start editing files in `content/`.

## Authoring tips

- Keep headlines short and specific (40–60 chars)
- Lead with the outcome, then steps
- Add `head.description` and `head.image` for shareable links
- Test on mobile and keyboard navigation before you publish
